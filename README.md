# Theme Park Odometry: Data and Scripts

This repository contains the data and analysis scripts used in our paper on smartphone-based inertial odometry for amusement ride trajectory reconstruction. Using smartphone acceleration and gyroscope data, we perform quaternion-based gyroscope integration, drift correction, and double integration to recover full 3D motion paths.

## Formule X

The `formule_x/` directory contains the core pipeline for reconstructing the trajectory of the Formule X roller coaster.

### Folder Structure

#### Core Processing Pipeline (`formule_x/`)
- `rotate_to_earth_frame.py`: Integrates gyroscope data to determine the phone's orientation over time, then rotates the raw 3D acceleration data into the fixed global Earth frame. Outputs `orientation.csv` and `accelerometer_earth.csv`.
- `rotate_to_cart_frame.py`: Projects the raw acceleration data into the ride carriage's local coordinate frame. Outputs `accelerometer_cart.csv`.
- `integrate_accel.py`: Performs gravity-corrected double numerical integration (trapezoidal) on the Earth-frame acceleration data to compute velocities and 3D positions. Outputs `motion_data.csv`.
- `rotation_common.py`: Provides shared utilities for vector-to-rotation mapping, heading alignment, and parsing various CSV formats.

#### Data Directories
- `data_raw_cut/`: Contains the raw smartphone sensor data (`Accelerometer.csv` and `Gyroscope.csv`), pre-trimmed to match the duration of the ride.
- `data_processed/`: Contains intermediate and final output files generated by the processing pipeline:
  - `orientation.csv`: The estimated device orientation data over time (in quaternion and Euler angles).
  - `accelerometer_cart.csv`: Acceleration data expressed in the aligned carriage coordinate system.
  - `accelerometer_earth.csv`: Acceleration data expressed in the global Earth frame.
  - `motion_data.csv`: The integrated 3D trajectory (time, position, and velocity).
  - `turn_radius_18-21s.csv`: An example of derived metrics for a specific track segment.

#### Visualization and Export
- `plotting_scripts/`: 
  - `plot_acceleration.py`: Generates plots for the accelerometer signals (raw data, Earth frame, and carriage frame).
  - `plot_energy.py`: Calculates and plots the kinetic, gravitational potential, and total energy.
  - `plot_gyroscope.py`: Visualizes the raw angular velocities.
- `google_earth/`:
  - `convert_earth.py`: Transforms the local 3D trajectory into global geodetic coordinates (latitude, longitude, altitude) for visualization over satellite imagery.
  - `motion_path_corrected.kml`: The resulting trajectory file, which can be viewed in Google Earth.
- `plots/`: The output directory for the generated figures.
- `unused_plotting_scripts/`: Contains a script to animate the reconstructed roller coaster path and another to plot the turn radius during the first loop.

### Workflow

To reproduce the analysis, execute the scripts in the following order:

1. **Orientation and Global Frame Alignment:** Run `rotate_to_earth_frame.py` to calculate the device's orientation and yield Earth-referenced acceleration data.
2. **Trajectory Integration:** Run `integrate_accel.py` to subtract gravity and double-integrate the Earth-frame acceleration data into velocities and positions.
3. **Carriage Frame Analysis (Optional):** Run `rotate_to_cart_frame.py` if carriage-frame data is required.
4. **Visualization:** Run any of the scripts in `plotting_scripts/` to generate graphs, use `google_earth/convert_earth.py` to create a map overlay, or explore the `unused_plotting_scripts/` directory to animate the path and analyze the turn radius.

### Applying to a Different Roller Coaster

If you want to apply this repository's code to data from a different roller coaster, you will need to adjust several coaster-specific parameters. These parameters govern how the scripts extract gravity profiles and align heading directions based on launch acceleration.

At the top of the core processing scripts (`rotate_to_earth_frame.py`, `rotate_to_cart_frame.py`, and `integrate_accel.py`), you will find a settings block labeled `--- COASTER SPECIFIC SETTINGS ---`. 

Key values you might need to adjust include:
- `STATIONARY_WINDOW`: Duration (in seconds) at the very start and end of the trim window where the phone is completely stationary to estimate baseline gravity and establish the Zero Velocity Update (ZUPT) intervals for drift correction.
- `LAUNCH_WINDOW`: Duration (in seconds) to average the launch acceleration.
- `LAUNCH_MIN_ACCEL` & `LAUNCH_MAX_ACCEL`: The expected horizontal acceleration threshold bounds (in m/s²) that the script uses to auto-detect the launch event and align the X/Y axes correctly.
- `LAUNCH_SLOPE`: The launch slope is used for azimuthal alignment. It is the ratio dy/dx where +y is the North direction and +x is the East direction. This is needed for a correct Google Earth overlay.

## De Piraat

The `de_piraat/` directory contains the main analysis script (`Projoct.py`) which handles all loading, correction, integration and plotting of data.

### Structure
#### Projoct.py

`Projoct.py` works by importing acceleration and orientation data generated by Phyphox, applying rotation to transform this data into a fixed laboratory frame, and subsequently integrating this acelleration data. This is repeated twice to apply corrections, which ensure the final speed and position are zero.

#### Parameters

 - useRotation: Should the orientation data be used?
 - useCorrection: Should a correction be applied, which unifies the final speed and position with the start speed and position?
 - plotCalculatedPositions: Generate 3D plot of integrated positions
 - plotCalculatedVelocities: Generate plot of individual velocity components
 - plotAcceleration: Generate plot of individual accelerations
 - plotAbsVelocity: Generate plot of norm of velocities
 - plotAbsAcceleration: Generate plot of norm of accelerations
 - plotEnergies: Generate plot of specific energies (Kinetic & Potential) (This function needs to be modified to best suit your requirements)
 - plotOrientation: Generate plot of euler angles of smartphone
 - plot2DPath: This function unifies the x, y axes to generate a 2D path plot, useful for circular motions. Also generates a circular curvefit through path.
 - plotCalculatedRadii: Function which roughly calculates the radius of the swinging motion based on velocity and acceleration
